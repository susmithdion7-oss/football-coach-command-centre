# Coach Command Centre / 教练罗盘

App 产品计划书 v1.0

This is the master product blueprint for Coach Command Centre / 教练罗盘. Use it for long-term product direction, major UI or module redesigns, roadmap planning, feature prioritisation, and strategic decisions.

## 1. 产品一句话定位

Coach Command Centre / 教练罗盘 是一款 coach-first 的足球教练个人工作系统，帮助青训、基层、业余和发展中教练建立自己的 Coach HQ，系统化管理球员发展、训练设计、战术板、比赛准备、赛后复盘和教练成长。

它不是普通球队行政管理软件，而是一个让教练真正感觉自己在带队、在建设球队、在推动球员成长的执教系统。

一句话可以这样描述：

教练罗盘是年轻教练自己的足球执教总部：管理球员、设计训练、制作战术、复盘比赛、追踪成长，并把每一次训练和比赛转化成下一步行动。

## 2. 产品愿景

Coach Command Centre 最终应该成为一个真正的 Coach HQ / Coach Mission Control。

它不是一个普通 admin dashboard，也不是一个简单的表格工具。它应该让教练打开后立刻感觉：

- 这是我的球队。
- 这是我的球员。
- 这是我的赛季。
- 这是我的训练计划。
- 这是我的战术思路。
- 这是我作为教练持续成长的系统。

### 2.1 Coach-first，而不是 club-first

市面上很多 grassroots football app 更偏向俱乐部行政管理，例如：

- 队费
- 家长沟通
- 通知
- 比赛报名
- 队务管理
- 出勤
- 日程

这些很有价值，但不是你的产品核心。

教练罗盘的核心用户不是俱乐部管理员，而是教练本人。

它要解决的是：

- 我怎么带好这支队？
- 我怎么知道球员有没有进步？
- 我怎么设计下一堂训练？
- 我怎么把比赛问题转化成训练重点？
- 我怎么记录我的执教思考？
- 我怎么形成自己的教练体系？

### 2.2 Coach HQ，而不是网页后台

Dashboard 不应该是普通首页，应该是 Coach Mission Control。

Players 不应该是球员卡片页，应该是 Player Operating System。

Session Planner 不应该是一张训练表格，应该是 Session Design Studio。

Tactical Board 不应该只是一个画图工具，应该是 Tactical Workstation / Presentation Tool。

Match Centre 不应该只是赛程表，应该是 Match Preparation & Reflection Loop。

### 2.3 像现实版轻量 Football Manager，但必须真实可用

你的目标不是做游戏，但可以借鉴 FC / Football Manager 的心理体验：

- 接手球队
- 建立球队身份
- 管理阵容
- 关注球员成长
- 准备比赛
- 调整战术
- 复盘表现
- 推进赛季

产品最终的感觉应该是：

FC Manager Mode 的沉浸感 + Apple app 的清晰高级感 + 真实教练工作的实用性。

## 3. 目标用户

### 3.1 青训教练

青训教练需要持续关注球员发展，而不是只看比赛结果。

他们的痛点：

- 球员很多，进步情况难追踪
- 训练计划经常靠记忆或临时想
- 球员反馈没有系统沉淀
- 赛后问题很难转化成下一次训练
- 很难长期记录球员发展轨迹

教练罗盘可以帮助他们：

- 建立每个球员的发展档案
- 设定 development focus
- 记录训练反馈和比赛反馈
- 根据球员需求设计 session
- 形成长期成长记录

### 3.2 Grassroots 教练

基层教练通常没有完整的俱乐部分析团队，也没有复杂软件支持。

他们需要的是：

- 简单
- 好用
- 不复杂
- 但有专业感

他们不一定愿意用复杂的战术软件、数据平台或行政系统。

教练罗盘要让他们感觉：

我也可以像职业教练一样管理我的队。但不需要复杂学习成本。

### 3.3 业余教练

业余教练可能带成人业余队、周末球队、社区球队。

他们的痛点：

- 球员出勤不稳定
- 训练内容难持续
- 比赛复盘随口说完就没了
- 战术安排没有沉淀
- 队伍缺少长期目标

产品要帮助他们：

- 建立基础球队档案
- 管理阵容和比赛计划
- 记录球员状态
- 设计实用训练
- 形成战术和赛季目标

### 3.4 学校 / 大学球队教练

这类用户可能需要：

- 训练计划
- 球员名单
- 比赛记录
- 报告输出
- 赛季总结
- 球员发展评价

PDF export、player report、season review 对他们会很重要。

### 3.5 年轻发展中教练

这是非常重要的核心人群。

他们的特点：

- 有学习欲望
- 喜欢战术
- 喜欢分析
- 愿意试错
- 对 FC / Football Manager 有情绪连接
- 想让自己看起来更专业
- 希望建立自己的 coaching portfolio

教练罗盘可以成为他们的个人成长工具：

- 记录训练
- 反思比赛
- 整理球员反馈
- 形成教练档案
- 展示自己的执教体系

## 4. 用户心理与产品粘性

这个产品要成功，不能只是“能用”。它必须让教练产生：

- 身份感
- 成就感
- 掌控感
- 成长感
- 依赖感

### 4.1 身份感：我真的在带队

第一次进入 app 不应该直接看到 Dashboard，而应该像 FC manager mode 一样：

- Create New Team
- Explore Demo

用户点击 Create New Team 后，应该像“接手球队”：

- Coach Profile
- Team Identity
- Squad Setup
- Season Setup
- Coaching Direction
- Review & Launch

这会让用户感觉：

我不是在注册一个账号。我是在创建我的 Coach HQ。

### 4.2 成就感：我的球队正在变好

教练会持续使用，是因为他能看到正反馈：

- 球员档案越来越完整
- 球员 focus 越来越清楚
- 训练计划越来越系统
- 战术板越来越丰富
- 比赛问题能变成下一次训练
- 赛季目标有推进感

Dashboard 应该不断给教练反馈：

- 3 players need attention
- Next session 80% ready
- 4 coach tasks open
- 2 players improved this month

即使第一版没有复杂算法，也可以用规则生成正反馈。

### 4.3 掌控感：我知道下一步该做什么

好的 Dashboard 不是展示所有数据，而是告诉教练：

你现在该做什么。

例如：

- Finish next session plan
- Set development focus for 3 players
- Create your first tactical board
- Prepare match lineup
- Add coach notes after training

这会让 app 从“工具集合”变成“教练指挥中心”。

### 4.4 成长感：我作为教练也在进步

未来应该有 Coach Development / Coach Profile：

- 我的训练设计数量
- 我的反思记录
- 我的 session library
- 我的 match review
- 我的 player development history
- 我的 coach portfolio

这会让年轻教练觉得：

我不只是管理球队，我也在建立自己的执教履历。

### 4.5 避免“上班感”

用户不想打开 app 后看到：

- 一堆表格
- 一堆输入框
- 一堆空白卡片
- 一堆 administrative tasks

所以设计原则是：

- 首页看全局
- 列表看对象
- 点击看详情
- 弹窗做动作
- 工作区做设计
- 预览页做输出

不要让用户一进页面就面对巨大表单。

## 5. 产品核心差异化

### 5.1 和普通球队管理软件的区别

普通 grassroots / club admin app 往往围绕：

- 家长沟通
- 队费
- 赛程
- 出勤
- 通知
- 球队行政

教练罗盘围绕：

- 教练工作
- 球员发展
- 训练设计
- 战术可视化
- 比赛复盘
- 教练成长

### 5.2 和 Centre Circle 类 app 的区别

Centre Circle 这类产品更偏球队组织和基层俱乐部事务。

教练罗盘不应该直接和它比“谁更会管队务”，而是走不同方向：

- Centre Circle = team admin / club operations
- Coach Command Centre = coaching workflow / coach operating system

### 5.3 和简单 session plan maker 的区别

很多工具可以写训练计划，但它们通常是孤立的。

教练罗盘的 Session Planner 应该读取：

- 球员发展重点
- 上一次比赛问题
- 球队目标
- 教练目标
- 历史训练记录

然后帮助教练设计下一堂训练。

也就是说：

不是写一张 session plan，而是从球队问题生成训练设计。

### 5.4 核心闭环差异化

你的产品真正差异化是：

Player Development → Session Design → Tactical Board → Match Review → Player Feedback → Next Session

这是一个系统，而不是几个功能页面。

## 6. 整体系统闭环

教练罗盘最终应该形成完整闭环：

Team Identity → Player Profiles → Development Focus → Session Design → Tactical Board → Match Preparation → Match Review → Player Feedback → Next Session → Coach Reflection → Season Progress

### 6.1 Team Identity

用户先建立球队身份：

- 球队名称
- 年龄组
- 赛季
- 队徽
- 主色
- 教练姓名
- 球队目标
- 教练目标
- 比赛风格
- 训练重点

这决定整个系统的上下文。

### 6.2 Player Profiles

每个球员有自己的档案：

- 头像
- 号码
- 姓名
- 位置
- 惯用脚
- 年龄
- 发展重点
- notes
- training feedback
- match feedback
- 状态
- 阵容角色

### 6.3 Development Focus

每个球员可以有 development focus：

- Scanning
- First Touch
- Decision Making
- Finishing
- Defensive Shape
- Confidence
- Communication

这些 focus 会反向影响 Session Planner。

### 6.4 Session Design

Session Planner 根据：

- 球队目标
- 球员 focus
- 比赛问题
- 上次反思
- 教练目标

设计训练。

### 6.5 Tactical Board

训练中的活动和战术可以被可视化：

- diagram
- players
- cones
- balls
- areas
- arrows
- mini goals

Tactical Board 可以用于讲解，也可以嵌入 session。

### 6.6 Match Preparation

比赛前：

- 选择阵容
- 设置 formation
- 设置 tactics
- 设置 assignments
- 准备 match plan

### 6.7 Match Review

比赛后：

- 记录比分
- 记录表现
- 记录问题
- 记录球员反馈
- 记录战术问题

### 6.8 Player Feedback

训练和比赛反馈写回球员档案。

### 6.9 Next Session

系统根据反馈提醒：

- 下一次训练应该关注什么
- 哪些球员需要帮助
- 哪些问题重复出现

### 6.10 Coach Reflection

教练记录：

- What worked?
- What did not work?
- What should I change next time?
- Which player needs attention?

### 6.11 Season Progress

Dashboard 汇总：

- 球员成长
- 训练完成度
- 战术库
- 比赛复盘
- 赛季目标
- 教练任务

## 7. 核心模块总览

### 7.1 Onboarding / Team Setup

首次创建球队和教练身份。

### 7.2 Dashboard / Coach Mission Control

进入系统后的指挥中心，告诉教练下一步该做什么。

### 7.3 Players / Player Operating System

球员档案、发展重点、阵容、战术、角色分配。

### 7.4 Session Planner / Session Design Studio

训练设计系统，包含 session dashboard、wizard、workspace、activity timeline、diagram。

### 7.5 Tactical Board / Tactical Workstation

战术板、训练图、演示模式。

### 7.6 Match Centre

未来比赛准备、阵容、复盘、球员表现记录。

### 7.7 Calendar

未来显示训练、比赛、任务和复盘日程。

### 7.8 Reports

未来导出 session PDF、player report、match report、season review。

### 7.9 Coach Profile / Coach Development

未来记录教练个人目标、执教风格、成长记录、portfolio。

### 7.10 Settings / Team Identity

球队身份、主题色、队徽、赛季、教练信息。

### 7.11 Future AI Assistant

未来基于真实数据的智能助教，而不是普通聊天机器人。

## 8. Onboarding / Team Setup 详细设计

### 8.1 第一次进入不应该直接进 Dashboard

新用户第一次打开 app，不应该看到正式 dashboard、sidebar 和空模块。

应该先看到：

- Create New Team
- Explore Demo

这是“接手球队”的入口。

### 8.2 Create New Team 流程

推荐流程：

1. Coach Profile
2. Team Identity
3. Squad Setup
4. Season Setup
5. Coaching Direction
6. Review & Launch

### 8.3 Coach Profile

字段：

- Coach name
- Role
- Coaching style
- Main coaching focus
- Coach photo upload
- Coach motto

要支持 custom input。

不要限制教练只能选系统预设。

### 8.4 Team Identity

字段：

- Team name
- Club name
- Age group
- Team type
- Primary team colour
- Team crest upload
- Team motto

重点：

- 只需要 primary team colour
- 不要一开始强制 home/away kit 复杂设置
- 颜色要驱动整个 UI

### 8.5 Squad Setup

不要强迫用户一个一个创建球员。

必须支持：

- Import Squad File
- Paste Player List
- Add Player Manually
- Start Empty

Paste 格式示例：

```text
Jake Smith, 7, CM, Right
Oscar Brown, 9, ST, Left
```

原则：

- 只有 name 必填
- 号码、位置、惯用脚都可以后补

### 8.6 Season Setup

字段：

- Season name
- Training days
- Training time
- Training venue
- Match day
- Competition / league
- Default session duration

### 8.7 Coaching Direction

字段：

- Team playing style
- Training priorities
- Season objectives
- Coach objectives

每项都要：

- 有 presets
- 也允许 custom
- 不要按钮墙
- 最多选 2-3 个

### 8.8 Review & Launch

最后显示：

- Coach Profile complete
- Team Identity complete
- Squad ready
- Season setup
- Coaching direction

按钮：

- Enter Coach HQ

这一刻要有仪式感。

## 9. Dashboard / Coach Mission Control 详细设计

Dashboard 的核心不是展示数据，而是告诉教练：

下一步该做什么。

### 9.1 Dashboard 应该回答的问题

- 我是谁的 Coach HQ？
- 今天最重要的事是什么？
- 下一堂训练准备好了吗？
- 哪些球员需要关注？
- 下一场比赛是什么？
- 本周有什么安排？
- 我下一步应该点击哪里？

### 9.2 核心结构

- Compact Coach HQ Header
- Today’s Coach Focus
- Status Cards
- Main Work Grid
- Lower Supporting Panels

### 9.3 Today’s Coach Focus

这是最重要的区域。

包括三列：

#### Next Session

如果有 session：

- title
- date/time
- topic
- duration
- status
- Continue Planning

如果没有：

- Plan your next session
- Create Session

#### Players Need Attention

根据规则检测：

- missing position
- missing development focus
- no coach notes
- profile incomplete
- Needs Support

显示：

- 3 players need review
- Review Players

#### Next Match

如果没有 Match Centre 数据：

- Saturday Morning
- Opponent TBC
- Preparation not started
- Prepare Match

### 9.4 Status Cards

四个状态卡：

- Squad
- Sessions
- Match Prep
- Coach Tasks

它们不是普通统计，而是决策提示。

例：

```text
Squad
16 players
3 need attention
```

### 9.5 Main Work Grid

三个主要模块：

- Next Session Readiness
- Players Need Attention
- This Week

#### Next Session Readiness

检查：

- Objective
- Activities
- Diagram
- Coaching Points
- Player Questions

#### Players Need Attention

显示具体球员和原因。

#### This Week

显示本周训练、比赛、休息日、任务。

### 9.6 Lower Supporting Panels

- Tactical Board
- Recent Activity
- Season Objectives

### 9.7 Coach Tasks

规则生成任务：

- Add your first player
- Complete player positions
- Set development focus
- Create your next session
- Finish draft session
- Create first tactical board
- Prepare next match

不需要 AI。

## 10. Players / Player Operating System 详细设计

Players 不应该是球员卡片页，而应该是一个球员运营系统。

### 10.1 三大板块

- Player Centre
- Squad Management
- Development Plans

### 10.2 空 squad 状态

如果没有球员，不应该显示空球员详情和空阵容编辑器。

应该显示：

```text
Build your squad

Import your squad list or add players manually.
You can complete player details later.

[Import Squad List]
[Paste Player List]
[Add Player Manually]
```

同时显示：

```text
What you can track:
Position
Preferred foot
Development focus
Coach notes
Training feedback
Match feedback
```

### 10.3 Player Centre

有球员后显示：

- 左侧：Player List
- 右侧：Selected Player Detail Panel

#### Player List

每行：

- number
- position
- avatar
- name
- morale
- status
- actions

#### Selected Player Detail

显示：

- avatar
- shirt number
- name
- position
- age
- preferred foot
- availability
- morale
- training status
- development focus
- coach note summary
- profile completeness
- latest training feedback
- latest match feedback
- recent notes

### 10.4 Player Action Menu

点击球员 actions：

#### Profile

- Open Full Profile
- Edit Player Details
- Change Player Photo

#### Coaching

- Add Coach Note
- Log Training Feedback
- Log Match Feedback
- Set Development Focus

#### Squad

- Add to Starting XI
- Add to Bench
- Open in Squad Management

#### Danger

- Archive / Remove Player

危险操作必须 confirm。

### 10.5 Squad Management

包含：

- Lineup
- Tactics
- Assignments

#### Lineup

有球员时才显示阵容编辑器。

如果无球员：

```text
Build your squad before creating a lineup
```

Lineup 应该：

- 大球场为主舞台
- 点击位置 slot 选择球员
- 底部 bench card row
- 右侧 selected player panel

不应该在球场上到处放普通 select。

#### Tactics

包含：

- Formation
- Tactical preset
- Build-up style
- Defensive approach
- Pressing intensity
- Team width
- Tempo
- Focus area

阵型包括：

- 4-4-2

- 3-4-3
- 5-3-2
- 5-4-1
- 4-1-4-1

- 4-2-2-2

预设包括：

- Balanced
- Possession
- High Press
- Counter Attack
- Direct Play
- Long Ball
- Low Block
- Build from the Back
- Wide Play
- Fast Transition
- Compact Defending

#### Assignments

角色：

- Captain
- Vice Captain
- Penalty Taker
- Left Free Kick
- Right Free Kick
- Long Free Kick
- Left Corner
- Right Corner
- Left Throw-in
- Right Throw-in

### 10.6 Development Plans

未来模块，初期可以 placeholder。

最终应包括：

- individual objectives
- development trends
- training targets
- match feedback trends
- coach action plans

## 11. Session Planner / Session Design Studio 详细设计

Session Planner 是产品最重要的差异化模块之一。

它不能像一张大表格，因为教练不是来填表的，而是来设计训练的。

### 11.1 三层结构

- Session Dashboard
- Create Session Wizard
- Session Workspace
- Session Preview / PDF

### 11.2 Session Dashboard

显示：

- This Week
- Next Session
- Drafts
- Saved Sessions
- Session Library
- Focus Areas
- Session Quality Checklist
- Recently Delivered

### 11.3 Create Session Wizard

入口：

- Start from Scratch
- Build from Squad Needs
- Duplicate Previous Session

#### Start from Scratch

填写：

- age group
- players
- duration
- pitch size
- equipment
- topic
- game moment
- coaching style

#### Build from Squad Needs

读取：

- player development focus
- coach notes
- missing focus
- team goals
- match problems

第一版可以规则生成，不需要 AI。

#### Duplicate Previous Session

复制旧 session，方便教练复用。

### 11.4 Session Structure

模板：

- Simple 3-part session
- Standard 5-part session
- Match Prep Session
- Technical Session
- Low Numbers Session

### 11.5 Session Workspace

核心布局：

- 左侧：Activity Timeline

## 24. 风险和注意事项

### 24.1 不要过早加 AI

AI 是未来核心，但现在加会导致：

- 后端问题
- 成本问题
- 安全问题
- 产品还没稳定

先做好数据和 workflow。

### 24.2 不要过早做后端

现在最大问题是产品体验，不是云端。

先用 localStorage MVP 验证。

### 24.3 不要一次做太大

Codex 任务必须小。

每次一个模块，一个目标，一个 PR。

### 24.4 不要让 UI 失去统一性

这是当前最大问题之一。

必须有 DESIGN_SYSTEM。

### 24.5 不要每页不同风格

Players 可以 dark，但必须 follow club colour。

Dashboard light，Session light，Tactical dark，都要在同一设计系统下。

### 24.6 不要只做功能，不做体验

功能能跑不代表产品好用。

每个页面都要问：

- 教练下一步该做什么？
- 这个界面有没有让我想用？

### 24.7 不要忽视 localStorage 数据保护

必须：

- 不清空
- 不重命名 keys
- 危险操作 confirm
- 支持 export/import

### 24.8 不要过早商业化

先找 3-5 个教练测试。

确认核心 workflow 有价值，再考虑收费。

## 25. 最终总结

Coach Command Centre / 教练罗盘 是一个非常值得继续做的产品。

它的价值不在于做一个普通球队管理网页，而在于为基层、青训、业余和年轻发展中教练提供一个真正的 Coach HQ：

- 创建球队身份
- 管理球员发展
- 设计训练
- 制作战术图
- 准备比赛
- 复盘表现
- 记录反馈
- 推进赛季
- 沉淀教练成长

它最重要的方向是：

把教练的日常工作从零散、临时、靠记忆，变成一个有结构、有反馈、有成就感的系统。

下一步最应该做的不是继续盲目加功能，而是：

1. 统一设计系统
2. 完成 Dashboard Coach Mission Control
3. 打磨 Players empty state 和 Player Centre
4. 重构 Session Planner 为 Session Design Studio
5. 让 Tactical Board 成为真正讲解工具
6. 再建立 Match / Feedback / Reports 闭环

最终目标是让教练每天打开 app 时，不是觉得自己在填表，而是觉得：

我正在带领我的球队前进。
